# Portal i18n

## Adding user-visible text

1. **Modals, sentences, errors** — add keys under `src/i18n/portalNamespaces/` (or `resources.ts` / `faResources.ts` / `wave1Resources.ts`) and use `useTranslation('namespace')`.
2. **Short labels reused across screens** — add a row to `healthPlanPhrases.ts` (5 columns: en source key + es, fr, ar, fa) and render with `uiText('English label')`.
3. Do **not** add new strings only to `faPhrases.ts`; that catalog is legacy extraction.

## Locales (two independent settings)

| Setting                   | Scope              | Storage                          | Affects                                                                    |
| ------------------------- | ------------------ | -------------------------------- | -------------------------------------------------------------------------- |
| **Portal language**       | Per user           | `users.portal_ui_locale`         | i18next UI, RTL/LTR (`applyUiLocale`, `ClinicLocaleSync`)                  |
| **Content / AI language** | Per clinic (admin) | `clinics.default_content_locale` | Clinic-wide default for LLM generation and stored report/plan prose |

**Portal UI** wave-1 languages: `en`, `es`, `fr`, `ar`, `fa` (Settings still uses language + regional format dropdowns).

**Content / AI** uses a curated BCP-47 catalog (~90 tags) in:

- Backend: `Holisticare/packages/shared/locale/content_locale_catalog.py`
- Frontend: `src/i18n/contentLocaleCatalog.ts` (must stay in sync; see `contentLocaleCatalog.test.ts`)

Settings shows a **single searchable** picker (`ContentLocalePicker`) with labels like `English (UK)` for `en-GB`. To add a locale, append the canonical tag to **both** files and run backend + frontend tests.

Non-LLM merge labels (e.g. treatment-plan “Key Benefits”) still only have full translations for wave-1 languages; other content locales get English fallbacks for those strings.

First login: `LocaleSetupGate` collects portal language for every user; clinic admins can also set content language when the clinic has none yet.

Local storage key for UI cache: `holisticare.portalUiLocale` (legacy `holisticare.clinicContentLocale` is migrated once).

## AI-generated content

Stored report/plan prose follows the patient's health-plan language, not the portal UI language. That language is the clinic default unless Add Client or Edit Client saves Custom for that patient. A valid custom tag stays when the clinic language changes. A tag no longer in the catalog falls back to the clinic language at generation and keeps the saved tag. After a change that actually changes the effective language, the next report check rebuilds; already stored HTML and plans stay as they are until then.
